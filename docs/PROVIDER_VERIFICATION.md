# Provider integration and verification

Reviewed for the current extension against the official sources below. **No real account authorization or paid inference was performed.** Protocol fixtures, real local callback/cryptographic verification and Linux packaging tests are separate from live-service and Steam Deck acceptance.

## ChatGPT plan connection

Decky Pilot implements the [official local/open-source sign-in flow](https://developers.openai.com/siwc/token-sharing-open-source/sign-in), rather than copying another app's credentials. It runs a temporary listener on `127.0.0.1`, uses fresh state/nonce/PKCE, receives the issued public-client ID, verifies the signed ID token with discovered OpenAI JWKS and checks issuer, audience, expiry, nonce and account identity. A retained host UUID and separate client/account registrations support reauthorization. Pending authorization never replaces the active account before validation.

The [OSS overview](https://developers.openai.com/siwc/token-sharing-open-source) documents local/open-source eligibility and dynamic registration without a partner key or client secret. That establishes a documented route for this local plugin; it does **not** verify this user's account/workspace eligibility or SteamOS browser behavior. Paid/remote hosting has different requirements. No commercial partner approval is assumed.

The backend requests `chatgpt.tokens.use.direct`, stores only its own tokens in an owner-only local file, serializes rotating refreshes within its single Decky backend, and attempts discovered-endpoint refresh-token revocation on disconnect. If remote revocation fails, it clears local tokens and explicitly directs the user to ChatGPT Settings. Separate backend processes sharing the same credential directory are unsupported; use one loaded plugin instance per host. No browser-cookie reading, Codex credentials, device-code endpoint or client secret is used.

[Account models](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference) are fetched from `/v1/models` using the selected connection's token. The picker preserves visible entries, service ordering, `display_name` and `slug`. No model is silently selected. Inference uses public `/v1/responses`, `store=false`, `stream=true`, and consumes SSE through the terminal event. Partial, failed, incomplete and interrupted results do not become successful answers. Plan-limit errors pause automatic help; no API-key fallback occurs.

The [preview restrictions](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations) require omitting an output-token budget and other unsupported fields. Consequently this route cannot promise a hard server-side token/cost ceiling. Local output, request duration and automatic request counts remain bounded. Image input is allowed only for returned models independently listed as image-capable in the reviewed contract. An unknown slug stays text-only. The contract includes exact documented OpenAI model IDs; it does not advertise availability to an account.

**Still NOT RUN:** authorization with an eligible real account, plan grant/denial, real account catalog, refresh/revocation against OpenAI, live image inference, usage-limit behavior, system-browser opening and loopback return on Steam Deck. Browser launching uses the installed `@decky/ui` SteamClient `System.OpenInSystemBrowser` declaration. A desktop browser and the Python backend must share the device loopback; opening the URL on a different computer will not return to the Deck. Steam gaming mode, Desktop mode switching, UID/network namespaces and lifecycle need device testing.

## Developer APIs and Ollama

| Connection | Official method and implemented endpoints | Image gate | Account / billing boundary |
|---|---|---|---|
| OpenAI API (advanced) | API key, `/v1/models`, `/v1/responses` | Returned catalog plus exact [documented image-input model](https://developers.openai.com/api/docs/models) | Developer API billing is separate from ChatGPT plan use. |
| Claude | Console API key, `/v1/models`, `/v1/messages` | Exact reviewed model IDs; undocumented IDs stay text-only | [API authentication](https://platform.claude.com/docs/en/manage-claude/authentication) supports developer credentials. No Claude consumer login is offered. Use a single-workspace key; multi-workspace selection is not implemented. |
| Gemini | AI Studio API key, `v1beta/models`, `generateContent` | Reviewed image model; catalog filters supported generation methods | [API billing](https://ai.google.dev/gemini-api/docs/billing) and project quotas apply independently of Google consumer plans. |
| Grok | xAI API key, `/v1/language-models`, `/v1/responses` | Actual returned `input_modalities` must include `image`; absent/false means no image send | [API quickstart](https://docs.x.ai/developers/quickstart) requires an API key and API account/credits. Consumer subscriptions do not establish API entitlement. |
| Ollama | Explicitly approved endpoint, `/api/tags`, `/api/show`, `/api/chat` | [Model details](https://docs.ollama.com/api/show) must report `vision` immediately before image generation | [Local API](https://docs.ollama.com/api/tags); installed model/server required. An endpoint may itself use a cloud service. No consumer-account token scraping. |

The API adapters make real REST requests in production; offline tests substitute their transport. Catalog requests are explicit and send no game text or image. Cloud services whose catalog omits image modalities use a conservative, sourced allowlist. Older/custom text models remain usable without automatically receiving images. Claude/Gemini catalog cursors are followed for at most 20 pages/2,000 entries; remaining pagination is explicitly labelled partial. Only returned entries are shown. There is no guarantee that a catalog entry will successfully infer: account policies, retirement, quotas and authentication may still reject it.

[xAI models](https://docs.x.ai/developers/models), [language-model catalog](https://docs.x.ai/developers/rest-api-reference/inference/models), and [image understanding](https://docs.x.ai/developers/model-capabilities/images/understanding) were checked separately. The implementation never sends images to an image-generation model, never guesses an image capability from a model name, and never changes provider after an error.

## Verification boundaries

- **Simulated service tests:** OAuth state/nonce/issuer/audience/expiry/signature/permission failures, issued-client exchange, replay refusal, refresh rotation, failed revocation, SSE completion/failure/limits; all six catalog adapters; Grok image payload and text-only rejection; session/image-consent revocation, stale frames, game switch, ambiguity, clarification context and automatic timing/abstention.
- **Real local checks:** actual HTTP callback on a temporary loopback listener with a simulated identity service; JWT RSA signing and verification against generated test keys; actual browser rendering, metadata removal, frontend build and package assembly. Linux CI also imports the extracted Linux cryptographic/Pillow wheels and exercises the plugin lifecycle. These are not real-provider tests.
- **Steam Deck checks:** safe game-only acquisition, controller/keyboard, onboarding/browser callback, non-Steam detection, QAM overlays, sleep/resume, voice/audio routing and performance remain NOT RUN. See [capture findings](https://github.com/realfulvio/decky-pilot/blob/codex/deckpilot-mvp/docs/CAPTURE_VERIFICATION.md).
